# 11. 운영 자동화 가이드 (구글폼 + 구글시트 + Apps Script)

> 1인 운영자가 신청 접수 → DB 등록 → 리마인드 → 등급 관리를 반자동으로 돌리기 위한 실무 가이드.
> 폼 문항은 `10-신청폼-문항-설계.md`, 메시지 원문은 `06-카톡-메시지-템플릿.md`,
> 온보딩 시퀀스는 `09-리뷰어-모집-플레이북.md`, DB 컬럼 정의는 `07-리뷰어-DB-양식.csv`를 그대로 따른다.
> 여기서 자동화하는 것은 "판단이 필요 없는 반복 작업"뿐이다. **채널 감사·검수(대가표시 100% 확인)·등급 수동 해제는 끝까지 사람이 한다.**

---

## 1. 전체 아키텍처

```
[리뷰어]                          [운영자(1인)]
   │                                  ▲
   │ 신청 제출                        │ 확인·승인·복붙 발송
   ▼                                  │
┌─────────────┐   응답 자동 기록   ┌──────────────────────────────┐
│  구글폼      │ ────────────────▶ │  구글시트 (운영 원장 1개 파일)  │
│  (신청 폼)   │                   │  ├ [응답원본]   ← 폼 연결 탭    │
└─────────────┘                   │  ├ [리뷰어마스터]              │
                                  │  ├ [캠페인]                   │
                                  │  ├ [진행보드]                 │
                                  │  └ [지급대장]                 │
                                  └──────────┬───────────────────┘
                                             │ 컨테이너 바인딩
                                             ▼
                                  ┌──────────────────────────────┐
                                  │  Apps Script                 │
                                  │  ⓐ onFormSubmit (제출 트리거) │
                                  │     → 카톡ID 중복 검사        │
                                  │     → 마스터 자동 등록        │
                                  │       (상태='심사대기')       │
                                  │     → 웰컴 메시지 문안 생성   │
                                  │  ⓑ dailyDigest (매일 아침)    │
                                  │     → 마감 D-2/D-day/초과     │
                                  │       리마인드 문안 이메일     │
                                  │  ⓒ recalcStats (주 1회/수동)  │
                                  │     → 참여수·이행률·등급 재계산│
                                  └──────────┬───────────────────┘
                                             │ 문안·다이제스트 생성
                                             ▼
                                  ┌──────────────────────────────┐
                                  │  운영자 화면                  │
                                  │  · admin.html 대시보드 또는   │
                                  │    시트에서 직접 관리          │
                                  │  · 스크립트가 만든 문안을      │
                                  │    카톡에 복사-붙여넣기 발송   │
                                  └──────────────────────────────┘
```

### 왜 "카톡 자동 발송"이 아니라 "문안 생성 + 복붙"인가

- 카카오톡 **알림톡**(정보성 자동 발송)은 카카오 비즈니스 채널 개설 + 발송 대행사 계약 + **템플릿 사전 심사**가 필요하다. 템플릿 문구 하나 바꿀 때마다 재심사이며, 광고성 문구는 알림톡으로 못 보낸다. 초기 1인 개인사업자에게는 비용·심사 리드타임 대비 효익이 없다.
- 개인 카톡·오픈채팅에는 공식 발송 API가 없다. 비공식 자동화는 계정 제재 위험만 크다.
- 그래서 이 가이드의 기본 설계는 **"스크립트가 치환 완료된 문안을 만들어 주면, 운영자가 복사-붙여넣기로 발송"** 이다. 발송 자체는 30초, 문안 작성·대상 선별이 0초가 되는 것이 자동화의 목표다. 자동 발송 전환 기준은 5절 로드맵 참조.

## 2. 시트 구조

구글시트 파일 하나(`리뷰밋 운영 원장`)에 탭 5개. 탭 이름은 아래와 **정확히 일치**시켜야 스크립트가 동작한다 (바꾸려면 각 스크립트 상단 CONST 수정).

### 2-1. [응답원본] — 폼 응답 연결 탭

구글폼에서 "응답 → 시트에 연결"로 생성되는 탭. 폼 문항(`10-신청폼-문항-설계.md`)이 그대로 컬럼이 되며, **절대 컬럼을 삭제·재정렬하지 않는다** (동의 증빙 원본 보존). 맨 오른쪽에 수동 관리 열 3개를 직접 추가한다.

| 컬럼 | 출처 | 비고 |
|---|---|---|
| 타임스탬프 | 자동 | 개인정보 동의 시각 증빙 |
| (폼 문항 전체) | 자동 | 1-1 동의 ~ 4-4 지원 경로 |
| 상태 | 수동+스크립트 | 스크립트가 `심사대기(자동등록)`/`중복` 기록 → 운영자가 승인/보류/반려로 갱신 |

| 열 | 컬럼 | 기록 주체 |

## 3. Apps Script 3종

### 공통 설치 방법

1. 운영 원장 시트를 열고 **확장 프로그램 → Apps Script** (컨테이너 바인딩 프로젝트가 생성된다).
2. 좌측 톱니 **프로젝트 설정 → 시간대**가 `(GMT+09:00) Seoul`인지 확인 (마감일 계산의 기준).
3. 아래 스크립트 3개를 각각 별도 파일(`a_onFormSubmit.gs`, `b_dailyDigest.gs`, `c_recalcStats.gs`)로 붙여넣고 저장.
4. 각 스크립트의 상단 `CFG_*` 상수만 실제 환경(문항 제목·이메일·링크)에 맞게 수정한다. **시트 이름·컬럼 인덱스를 바꿀 일이 생기면 수정 지점은 CONST뿐이다.**
5. 첫 실행 시 권한 승인 창이 뜬다 — 본인 계정으로 승인 (스프레드시트·메일 권한).

### ⓐ onFormSubmit(e) — 신규 신청 자동 등록 + 웰컴 문안 생성

동작: 폼 제출 순간 → [리뷰어마스터]에서 **카톡ID 기준 중복 검사** → 신규면 `R###` 부여 후 마스터에 추가(상태=`심사대기`), 웰컴 메시지 문안을 S열에 생성 → [응답원본] 해당 행에 상태·DB ID 기록. 중복이면 마스터에 추가하지 않고 응답원본에 `중복(기존 R###)`만 표시.

```javascript
/** =====================================================================
 * ⓐ onFormSubmit — 폼 제출 시 리뷰어마스터 자동 등록 + 웰컴 문안 생성
 * 트리거: 이 함수에 "스프레드시트에서 / 양식 제출 시" 트리거 연결 (아래 설치 참조)
 * ===================================================================== */
var CFG_A = {
  MASTER_SHEET: '리뷰어마스터',
  RESPONSE_SHEET: '응답원본',

  // ── 구글폼 문항 제목 (폼의 문항 텍스트와 한 글자도 다르면 안 됨. 10-문항-설계 기준) ──
  Q_NAME: '성명 (실명)',
  Q_PHONE: '연락처 (휴대전화)',
  Q_KAKAO: '카카오톡 ID',
  Q_REGION: '거주지역 (시/군/구까지)',
  Q_CH_TYPE: '운영 채널 유형',
  Q_BLOG_URL: '블로그 URL',
  Q_INSTA: '인스타그램 URL 또는 @아이디',
  Q_VISITORS: '일평균 방문자 수 (블로그) 또는 팔로워 수 (인스타)',
  Q_CATEGORY: '주력 카테고리',
  Q_POSTS30: '최근 30일 발행(게시) 수',
  Q_EXP: '체험단 참여 경험',
  Q_MKT: '마케팅 정보 수신 동의 (선택)',
  Q_SOURCE: '지원 경로',

  // ── 리뷰어마스터 컬럼 인덱스 (1=A). A~Q = 07-CSV 헤더 순서 ──
  COL_ID: 1, COL_NAME: 2, COL_KAKAO: 3, COL_PHONE: 4, COL_CH_TYPE: 5,
  COL_URL: 6, COL_VISITORS: 7, COL_CATEGORY: 8, COL_REGION: 9,
  COL_MEMO: 17, COL_STATUS: 18, COL_WELCOME: 19,
  MASTER_COL_COUNT: 21,          // A~U

  // ── 응답원본의 수동 관리 열 (1행 헤더명으로 찾는다) ──
  RESP_H_STATUS: '상태',
  RESP_H_DBID: 'DB 등록 ID',

  // ── 웰컴 문안 치환 링크 (09-플레이북 D0 템플릿) ──
  OPENCHAT_LINK: '[오픈챗 링크]',
  GUIDE_LINK: '[04-가이드라인 링크]'
};

function onFormSubmit(e) {
  var lock = LockService.getDocumentLock();
  lock.waitLock(30000); // 동시 제출 시 ID 중복 부여 방지
  try {
    var ss = SpreadsheetApp.getActiveSpreadsheet();
    var master = ss.getSheetByName(CFG_A.MASTER_SHEET);
    var resp = ss.getSheetByName(CFG_A.RESPONSE_SHEET);
    var row = e.range.getRow();

    var name = nvA_(e, CFG_A.Q_NAME);
    var kakao = nvA_(e, CFG_A.Q_KAKAO);
    if (!name || !kakao) return; // 동의 거부 분기 등 불완전 응답은 건너뜀

    // 1) 중복 검사 (카톡ID, 대소문자·공백 무시)
    var kakaoNorm = kakao.toLowerCase();
    var last = master.getLastRow();
    if (last >= 2) {
      var ids = master.getRange(2, CFG_A.COL_ID, last - 1, 1).getValues();
      var kakaos = master.getRange(2, CFG_A.COL_KAKAO, last - 1, 1).getValues();
      for (var i = 0; i < kakaos.length; i++) {
        if (String(kakaos[i][0]).trim().toLowerCase() === kakaoNorm) {
          writeRespA_(resp, row, '중복(기존 ' + ids[i][0] + ')', String(ids[i][0]));
          return;
        }
      }
    }

    // 2) 신규 ID 부여 (기존 R### 최댓값 + 1)
    var maxNum = 0;
    if (last >= 2) {
      var allIds = master.getRange(2, CFG_A.COL_ID, last - 1, 1).getValues();
      allIds.forEach(function (r) {
        var m = String(r[0]).match(/^R(\d+)$/);
        if (m) maxNum = Math.max(maxNum, parseInt(m[1], 10));
      });
    }
    var newId = 'R' + ('000' + (maxNum + 1)).slice(-3);

    // 3) 응답 → DB 매핑 (10-문항-설계 매핑 표)
    var chRaw = nvA_(e, CFG_A.Q_CH_TYPE);
    var chType = chRaw === '둘 다' ? '네이버블로그+인스타그램'
               : chRaw.replace(/\s+/g, ''); // "네이버 블로그" → "네이버블로그"
    var blog = nvA_(e, CFG_A.Q_BLOG_URL);
    var insta = nvA_(e, CFG_A.Q_INSTA);
    var url = blog || insta; // 둘 다 운영 시 블로그가 대표
    var category = nvA_(e, CFG_A.Q_CATEGORY).split(/,\s*/)[0]; // 체크박스 첫 항목
    var memo = '30일 발행 ' + nvA_(e, CFG_A.Q_POSTS30)
             + ' / 체험단 경험 ' + nvA_(e, CFG_A.Q_EXP)
             + ' / 마케팅 동의 ' + (nvA_(e, CFG_A.Q_MKT) === '동의함' ? 'O' : 'X')
             + ' / 유입: ' + nvA_(e, CFG_A.Q_SOURCE)

    var welcome =
      name + '님, 리뷰밋 리뷰어 승인을 축하드려요 🎉\n' +

      '   (캠페인 공지가 모두 이곳에 올라와요)\n' +

    var newRow = new Array(CFG_A.MASTER_COL_COUNT).fill('');

    newRow[CFG_A.COL_KAKAO - 1] = kakao;
    newRow[CFG_A.COL_PHONE - 1] = normPhoneA_(nvA_(e, CFG_A.Q_PHONE));
    newRow[CFG_A.COL_CH_TYPE - 1] = chType;
    newRow[CFG_A.COL_URL - 1] = url;
    newRow[CFG_A.COL_VISITORS - 1] = nvA_(e, CFG_A.Q_VISITORS); // 감사 후 실측으로 보정
    newRow[CFG_A.COL_CATEGORY - 1] = category;
    newRow[CFG_A.COL_REGION - 1] = nvA_(e, CFG_A.Q_REGION);
    // 가입일(J)은 비워 둔다 — 승인 시 승인일을 기입 (10-문항-설계 규칙)
    newRow[10] = 0;              // 참여캠페인수
    newRow[12] = 0;              // 미이행횟수
    newRow[13] = 0;              // 노쇼횟수

    newRow[CFG_A.COL_WELCOME - 1] = welcome;
    master.appendRow(newRow);

    // 6) 응답원본에 결과 표기
    writeRespA_(resp, row, '심사대기(자동등록)', newId);
  } finally {
    lock.releaseLock();
  }
}

/** namedValues에서 문항 값 읽기 (없으면 빈 문자열) */
function nvA_(e, title) {
  var v = e.namedValues ? e.namedValues[title] : null;
  return v && v[0] ? String(v[0]).trim() : '';
}

/** 010-0000-0000 형식으로 통일 */
function normPhoneA_(p) {
  var d = p.replace(/\D/g, '');
  return d.length === 11 ? d.replace(/(\d{3})(\d{4})(\d{4})/, '$1-$2-$3') : p;
}

/** 응답원본의 상태 / DB 등록 ID 열(헤더명 검색)에 기록 */
function writeRespA_(resp, row, status, dbId) {
  var headers = resp.getRange(1, 1, 1, resp.getLastColumn()).getValues()[0];
  var cStatus = headers.indexOf(CFG_A.RESP_H_STATUS) + 1;
  var cDbId = headers.indexOf(CFG_A.RESP_H_DBID) + 1;
  if (cStatus > 0) resp.getRange(row, cStatus).setValue(status);
  if (cDbId > 0) resp.getRange(row, cDbId).setValue(dbId);
}
```

### ⓑ dailyDigest() — 매일 아침 마감 리마인드 다이제스트 이메일

동작: [진행보드]에서 결과=`진행중`이고 리뷰URL이 비어 있는 행을 훑어 **발행마감 D-2 / D-day / 마감 초과** 3그룹으로 분류 → 각 리뷰어별로 `06-카톡-메시지-템플릿.md`의 **4번(D-2 리마인드)·5번(최종 독촉)** 문안을 치환 완성해 운영자 이메일로 발송. 운영자는 메일을 열고 문안을 그대로 카톡에 복붙만 하면 된다.

```javascript
/** =====================================================================
 * ⓑ dailyDigest — 발행마감 D-2 / D-day / 초과 리마인드 다이제스트 메일
 * 트리거: 시간 기반, 매일 오전 8~9시 (아래 설치 참조)
 * ===================================================================== */
var CFG_B = {
  BOARD_SHEET: '진행보드',
  ADMIN_EMAIL: 'operator@example.com',   // ★ 운영자 이메일로 수정
  TZ: 'Asia/Seoul',
  GUIDE_LINK: '[04-가이드라인 링크]',

  // ── 진행보드 컬럼 인덱스 (1=A) ──
  COL_CAMP_NAME: 2,   // B 캠페인명
  COL_RID: 3,         // C 리뷰어ID
  COL_RNAME: 4,       // D 성명
  COL_KAKAO: 5,       // E 카톡ID
  COL_DEADLINE: 10,   // J 발행마감일
  COL_URL: 11,        // K 리뷰URL
  COL_RESULT: 15,     // O 결과

  RESULT_ONGOING: '진행중'
};

function dailyDigest() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var board = ss.getSheetByName(CFG_B.BOARD_SHEET);
  var last = board.getLastRow();
  var d2 = [], dday = [], overdue = [];

  if (last >= 2) {
    var data = board.getRange(2, 1, last - 1, board.getLastColumn()).getValues();
    var today = new Date();
    today.setHours(0, 0, 0, 0);

    data.forEach(function (r) {
      var result = String(r[CFG_B.COL_RESULT - 1]).trim();
      var url = String(r[CFG_B.COL_URL - 1]).trim();
      var deadline = r[CFG_B.COL_DEADLINE - 1];
      if (result !== CFG_B.RESULT_ONGOING || url || !(deadline instanceof Date)) return;

      var dl = new Date(deadline);
      dl.setHours(0, 0, 0, 0);
      var diff = Math.round((dl - today) / 86400000); // 남은 일수
      var item = {
        camp: r[CFG_B.COL_CAMP_NAME - 1],
        rid: r[CFG_B.COL_RID - 1],
        name: r[CFG_B.COL_RNAME - 1],
        kakao: r[CFG_B.COL_KAKAO - 1],
        deadline: dl,
        diff: diff
      };
      if (diff === 2) d2.push(item);
      else if (diff === 0) dday.push(item);
      else if (diff < 0) overdue.push(item);
    });
  }

  var todayStr = Utilities.formatDate(new Date(), CFG_B.TZ, 'M월 d일 (E)');
  var total = d2.length + dday.length + overdue.length;
  var subject = '[리뷰밋] ' + todayStr + ' 리마인드 ' + total + '건'
              + ' (D-2 ' + d2.length + ' / D-day ' + dday.length + ' / 초과 ' + overdue.length + ')';

  var body = '리뷰밋 데일리 다이제스트 — ' + todayStr + '\n'
           + '아래 문안을 각 리뷰어 카톡에 그대로 복사-붙여넣기 하세요.\n'
           + '========================================\n\n';

  body += sectionB_('① 마감 D-2 (' + d2.length + '명) — 템플릿 4번', d2, msgD2_);
  body += sectionB_('② 마감 D-day (' + dday.length + '명) — 템플릿 5번', dday, msgDday_);
  body += sectionB_('③ 마감 초과 (' + overdue.length + '명) — 템플릿 5번 + 후속 처리', overdue, msgOverdue_);

  if (overdue.length) {
    body += '※ 초과 건 처리 기준: 최종 독촉 후 48시간 무응답 시 진행보드 결과를 "미이행"으로 변경\n'
          + '   → 주간 recalcStats 실행 시 등급에 자동 반영됩니다 (미이행 1회=C, 2회 누적=제외).\n\n';
  }
  if (total === 0) body += '오늘은 리마인드 대상이 없습니다. 좋은 하루 되세요!\n';

  MailApp.sendEmail(CFG_B.ADMIN_EMAIL, subject, body);
}

/** 그룹 섹션 문자열 생성 */
function sectionB_(title, items, msgFn) {
  var s = '--- ' + title + ' ---\n\n';
  if (!items.length) return s + '(없음)\n\n';
  items.forEach(function (it) {
    s += '▷ ' + it.rid + ' ' + it.name + ' (카톡: ' + it.kakao + ') — ' + it.camp
      + ' / 마감 ' + Utilities.formatDate(it.deadline, CFG_B.TZ, 'M월 d일') + '\n'
      + '┌ 복붙 문안 ─────────────\n'
      + msgFn(it) + '\n'
      + '└───────────────────\n\n';
  });
  return s;
}

/** 06-템플릿 4번: 발행 리마인드 (마감 D-2) */
function msgD2_(it) {
  return it.name + '님, ' + it.camp + ' 리뷰 마감이 이틀 남았어요 ⏰\n'
       + '마감: ' + Utilities.formatDate(it.deadline, CFG_B.TZ, 'M월 d일') + '\n'
       + '가이드라인: ' + CFG_B.GUIDE_LINK + '\n'
       + '어려운 점 있으시면 미리 말씀 주세요. 조율 가능해요!';
}

/** 06-템플릿 5번: 최종 독촉 (마감일) */
function msgDday_(it) {
  return it.name + '님, 오늘이 ' + it.camp + ' 리뷰 마감일이에요.\n'

/** 마감 초과: 템플릿 5번 변형 (경과일 명시) */
function msgOverdue_(it) {
  var over = Math.abs(it.diff);
  return it.name + '님, ' + it.camp + ' 리뷰 마감일이 ' + over + '일 지났어요.\n'
```

### ⓒ recalcStats() — 참여수·이행률·등급 일괄 재계산

동작: [진행보드]의 종결 결과(완주/미이행/노쇼)를 리뷰어ID별로 집계 → [리뷰어마스터]의 참여캠페인수·이행률(%)·미이행횟수·노쇼횟수·최근참여일을 갱신하고, 등급 규칙(운영 매뉴얼과 동일)으로 등급을 재판정한다. **등급고정(U열)=`Y`인 행의 등급은 건드리지 않는다** (C등급 수동 해제 보호).

등급 판정 순서 (위에서부터 먼저 걸리는 규칙 적용):

1. **제외** — 미이행 2회 누적 (선정 불가, 수동 해제 없음)
2. **휴면** — 최근참여일(참여 이력 없으면 가입일)로부터 90일 무참여
3. **C** — 미이행 또는 노쇼 1회 (선정 보류 — 해제는 수동: 등급 수정 + 등급고정 `Y`)
4. **A** — 완주 3회 이상 그리고 이행률 100%
5. **B** — 이행률 80% 이상
6. (공란) — 신규(종결 이력 없음)

```javascript
/** =====================================================================
 * ⓒ recalcStats — 진행보드 → 리뷰어마스터 참여수·이행률·등급 재계산
 * 실행: 시트 메뉴 [리뷰밋 자동화 > 등급 재계산] 또는 주 1회 시간 트리거
 * ===================================================================== */
var CFG_C = {
  MASTER_SHEET: '리뷰어마스터',
  BOARD_SHEET: '진행보드',
  TZ: 'Asia/Seoul',
  DORMANT_DAYS: 90,

  // ── 진행보드 컬럼 (1=A) ──
  B_COL_RID: 3,        // C 리뷰어ID
  B_COL_SELECTED: 7,   // G 선정일
  B_COL_PUB: 12,       // L 발행일
  B_COL_RESULT: 15,    // O 결과

  // ── 리뷰어마스터 컬럼 (1=A) ──
  M_COL_ID: 1,         // A ID
  M_COL_JOIN: 10,      // J 가입일
  M_COL_COUNT: 11,     // K 참여캠페인수
  M_COL_RATE: 12,      // L 이행률(%)
  M_COL_FAIL: 13,      // M 미이행횟수
  M_COL_NOSHOW: 14,    // N 노쇼횟수
  M_COL_GRADE: 15,     // O 등급
  M_COL_LAST: 20,      // T 최근참여일
  M_COL_LOCK: 21,      // U 등급고정

  RESULT_DONE: '완주',
  RESULT_FAIL: '미이행',
  RESULT_NOSHOW: '노쇼'
};

function recalcStats() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var board = ss.getSheetByName(CFG_C.BOARD_SHEET);
  var master = ss.getSheetByName(CFG_C.MASTER_SHEET);

  // 1) 진행보드 집계: 리뷰어ID → {완주, 미이행, 노쇼, 최근참여일}
  var stats = {};
  var bLast = board.getLastRow();
  if (bLast >= 2) {
    var bData = board.getRange(2, 1, bLast - 1, board.getLastColumn()).getValues();
    bData.forEach(function (r) {
      var rid = String(r[CFG_C.B_COL_RID - 1]).trim();
      if (!rid) return;
      if (!stats[rid]) stats[rid] = { done: 0, fail: 0, noshow: 0, lastDate: null };
      var st = stats[rid];

      var result = String(r[CFG_C.B_COL_RESULT - 1]).trim();
      if (result === CFG_C.RESULT_DONE) st.done++;
      else if (result === CFG_C.RESULT_FAIL) st.fail++;
      else if (result === CFG_C.RESULT_NOSHOW) st.noshow++;

      // 최근참여일 = 발행일 우선, 없으면 선정일 (진행중 포함 — 활동 중이면 휴면 아님)
      var d = r[CFG_C.B_COL_PUB - 1] instanceof Date ? r[CFG_C.B_COL_PUB - 1]
            : (r[CFG_C.B_COL_SELECTED - 1] instanceof Date ? r[CFG_C.B_COL_SELECTED - 1] : null);
      if (d && (!st.lastDate || d > st.lastDate)) st.lastDate = d;
    });
  }

  // 2) 마스터 갱신
  var mLast = master.getLastRow();
  if (mLast < 2) return;
  var width = CFG_C.M_COL_LOCK; // A~U
  var mData = master.getRange(2, 1, mLast - 1, width).getValues();
  var today = new Date();
  var changed = 0;

  mData.forEach(function (row) {
    var id = String(row[CFG_C.M_COL_ID - 1]).trim();
    if (!id) return;
    var st = stats[id] || { done: 0, fail: 0, noshow: 0, lastDate: null };
    var total = st.done + st.fail + st.noshow;
    var rate = total > 0 ? Math.round((st.done / total) * 100) : '';

    row[CFG_C.M_COL_COUNT - 1] = total;
    row[CFG_C.M_COL_RATE - 1] = rate;
    row[CFG_C.M_COL_FAIL - 1] = st.fail;
    row[CFG_C.M_COL_NOSHOW - 1] = st.noshow;
    row[CFG_C.M_COL_LAST - 1] = st.lastDate || '';

    // 등급고정 Y면 등급 유지 (C등급 수동 해제 보호)
    var locked = String(row[CFG_C.M_COL_LOCK - 1]).trim().toUpperCase() === 'Y';
    if (!locked) {
      row[CFG_C.M_COL_GRADE - 1] = gradeC_(st, total, rate, row[CFG_C.M_COL_JOIN - 1], today);
    }
    changed++;
  });

  master.getRange(2, 1, mData.length, width).setValues(mData);
  SpreadsheetApp.getActiveSpreadsheet().toast(
    changed + '명 재계산 완료 (' + Utilities.formatDate(today, CFG_C.TZ, 'M/d HH:mm') + ')',
    '리뷰밋 등급 재계산');
}

/** 등급 판정 — 00-운영-매뉴얼 등급제 규칙과 동일 */
function gradeC_(st, total, rate, joinDate, today) {
  if (st.fail >= 2) return '제외';                       // 미이행 2회 누적 → 선정 불가

  var baseDate = st.lastDate || (joinDate instanceof Date ? joinDate : null);
  if (baseDate) {
    var days = Math.floor((today - baseDate) / 86400000);
    if (days > CFG_C.DORMANT_DAYS) return '휴면';        // 90일 무참여
  }

  if (st.fail >= 1 || st.noshow >= 1) return 'C';        // 선정 보류 (수동 해제 가능)
  if (st.done >= 3 && rate === 100) return 'A';          // 완주 3회↑ + 이행률 100%
  if (rate !== '' && rate >= 80) return 'B';             // 이행률 80%↑
  return '';                                             // 신규 — 첫 완주 후 산정
}

/** 시트 메뉴에 실행 버튼 추가 (시트를 열 때 자동 실행됨) */
function onOpen() {
  SpreadsheetApp.getUi()
    .createMenu('리뷰밋 자동화')
    .addItem('등급 재계산 (recalcStats)', 'recalcStats')
    .addItem('다이제스트 즉시 발송 (dailyDigest)', 'dailyDigest')
    .addToUi();
}
```

**실행 방법**: 시트 상단 메뉴 **리뷰밋 자동화 → 등급 재계산** (금요일 주간 루틴). 자동화하려면 트리거 추가 → 함수 `recalcStats` / **시간 기반** / **주 단위 타이머** / 금요일 오전.
**주의**: 재계산은 K·L·M·N·O·T열을 덮어쓴다. 등급을 수동으로 고친 리뷰어는 반드시 **U열 등급고정=`Y`**를 함께 표시할 것.

## 5. 확장 로드맵

### 월 20캠페인(동시 진행 리뷰어 100명+) 도달 시 — 알림톡 자동 발송 전환

복붙 발송이 하루 30분을 넘기 시작하는 시점. 이때는 초기 비용을 치를 효익이 생긴다.

1. **카카오 비즈니스 채널** 개설 (사업자등록 필요 — 이미 보유)
2. 알림톡 발송 대행사(예: 국내 문자·알림톡 API 사업자) 계약 → 발신프로필 등록
3. **템플릿 사전 심사** 등록: 선정 안내·발행 리마인드(D-2)·최종 독촉 등 **정보성** 메시지부터. 모집 공지 같은 광고성 메시지는 알림톡 불가 — 오픈채팅 공지 유지
4. Apps Script의 `dailyDigest`를 "메일 발송" 대신 대행사 REST API 호출(`UrlFetchApp`)로 교체 — 문안 생성 로직은 그대로 재사용
5. 심사 리드타임(영업일 2~3일)과 템플릿 변수 규칙 때문에, 문구는 이 가이드의 치환 템플릿 구조를 유지해야 이관이 쉽다

### 자체 DB 웹앱 전환 기준

다음 중 2개 이상 해당되면 구글시트 졸업을 검토한다.

- 리뷰어 500명+ 또는 진행보드 누적 5,000행+ (시트 조회·재계산 체감 지연)
- 운영자 2인 이상 동시 편집으로 데이터 충돌 발생
- 리뷰어 셀프서비스 필요 (마이페이지에서 마감·등급·지급 내역 직접 확인)
- 지급대장·지급명세서를 세무 소프트웨어와 API 연동해야 할 때

전환 시에도 **[리뷰어마스터] A~Q열 = `07-리뷰어-DB-양식.csv` 헤더**를 유지해 왔다면 CSV 내보내기 한 번으로 마이그레이션이 끝난다. 이것이 2-2절에서 컬럼 순서를 고정한 이유다.

### 어떤 규모에서도 자동화하지 않는 것

- **대가표시 검수** — 100% 사람 눈으로 확인. 누락은 무조건 반려 (절대 원칙)
- 별점·내용·상위노출 보장, 구매평(상품평) 대가 캠페인 — 규모와 무관하게 하지 않는 사업
- 등급 제외·C등급 해제 판단 — 스크립트는 기록하고, 결정은 운영자가 한다
