# 소싱 레이더

네이버 공식 API로 소싱 후보를 **자동 채점**한다. 키워드 목록을 넣으면 상품 수·월간 검색 수·2년치 트렌드를 긁어와 경쟁강도와 역산 판매가를 계산하고, 100점 만점으로 줄 세워 CSV·JSON·HTML로 뱉는다.

수동으로 하면 아이템당 20분씩 걸리던 일이 20개 기준 2분에 끝난다.

## 왜 로컬에서 도는가

이 도구는 **당신 PC(또는 당신 GitHub Actions)에서** 실행해야 한다. 네이버 API는 국내에서 열려 있고, 이 저장소를 만든 개발 환경은 네트워크 정책상 네이버·쿠팡에 접근할 수 없었다. 코드는 목 서버로 전 구간 검증돼 있으니, 키만 넣으면 그대로 돈다.

## 1. 키 발급 (한 번만, 약 10분)

**네이버 개발자센터** — https://developers.naver.com/apps
1. 애플리케이션 등록
2. 사용 API에 **검색**과 **데이터랩(검색어 트렌드)** 둘 다 체크
3. `Client ID` / `Client Secret` 복사
4. 무료. 하루 25,000회.

**네이버 검색광고** — https://searchad.naver.com → 도구 → API 사용관리
1. 네이버 검색광고 계정 생성(광고 집행 없이도 가능)
2. `액세스 라이선스`(API 키) / `비밀키` / `Customer ID` 복사
3. 무료.

## 2. 설치

```bash
cd sourcing-radar
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp config.example.toml config.toml   # config.toml은 .gitignore에 있다
```

`config.toml`에 키를 채운다. 환경변수(`NAVER_CLIENT_ID` 등)를 쓰면 그쪽이 우선한다.

## 3. 실행

```bash
python -m radar.cli scan --keywords keywords.csv --out out
open out/radar.html
```

```
[1/4] 상품 수 조회 (20개)
[2/4] 월간 검색 수 조회
[3/4] 검색어 트렌드 조회
[4/4] 채점

완료 — 후보 20개 중 발주 검토 7개, 진입 창 2개
   1. [ 96] 무타공 욕실선반 (경쟁강도 0.13)
   2. [ 94] 피클볼 라켓세트 (경쟁강도 0.05)
```

## 4. 키워드 파일

`keywords.csv`에 20종이 이미 채워져 있다. 열 설명:

| 열 | 필수 | 뜻 |
|---|---|---|
| `item` | | 표시용 이름 |
| `keyword` | ✅ | 실제 조회할 검색어. **띄어쓰기 없이** |
| `unit_cost` | | 예상 원가(원). 없으면 마진 항목 0점 |
| `market_price_cap` | | 시장 상단 가격. 역산가가 이걸 넘으면 상단가 기준 마진으로 평가 |
| `shoppable` | | 쇼핑성 0–10. 검색 시 쇼핑 영역이 안 뜨면 0 |
| `logistics` | | 물류 난이도 0–10. 경량·비파손일수록 높게 |
| `cert` | | 인증 부담 0–10. KC 필수면 0–3 |
| `expansion` | | 확장성 0–5. 리필·세트가 되면 높게 |

`unit_cost`는 추정치로 채워 뒀다. **실제 견적으로 바꾸는 것이 이 도구를 쓰는 첫 번째 일이다.**

## 5. 채점 방식

| 항목 | 배점 | 만점 조건 |
|---|---|---|
| 경쟁강도 | 25 | 0.3 이하 |
| 검색 추이 | 15 | 전년비 +10% 이상 |
| 쇼핑성 | 15 | 쇼핑 영역 최상단 노출 |
| 마진 | 20 | 순마진 35% 이상 |
| 물류 | 10 | 경량·비파손·표준 택배 |
| 인증 | 10 | 인증 불필요 |
| 확장성 | 5 | SKU 확장 가능 |

**하드 게이트** — 점수와 무관하게 즉시 탈락:
- 경쟁강도 > `comp_max`(기본 0.7)
- 순마진 < `floor_margin`(기본 25%)

판정: 75점 이상 `발주 검토` / 60–74 `보류` / 그 아래 `탈락`.

### 경쟁강도

```
경쟁강도 = 상품 수 ÷ 월간 총검색 수
```

1을 넘으면 그 키워드를 검색하는 사람보다 그 키워드로 파는 사람이 더 많다는 뜻이다. 광고를 쓰지 않을 것이므로 검색량보다 이 지표가 먼저다.

### 마진 역산

```
판매가 = (원가 + 택배비 + 물류비) ÷ (1 − 변동비율 − 목표마진율)
변동비율 = 판매수수료 + 결제수수료 + 광고비 + 반품충당 + 부가세
```

가격을 정한 뒤 마진을 확인하는 게 아니라, **목표 마진을 먼저 박고 판매가를 역산**한다. 나온 가격이 시장 상단을 넘으면 그 아이템은 거기서 끝이다.

> 로켓그로스를 쓴다면 `config.toml`의 `fulfillment_cost`에 입출고·보관료를 **반드시** 채워라. 이걸 빼놓으면 판매가 5배 늘고 이익이 0이 되는 일이 실제로 벌어진다.

### 진입 창

두 가지 모양을 잡는다.
1. **유행성 급등** — 최근 3개월 평균이 직전 12개월 평균의 3배 이상
2. **지속 성장** — 전년비 +50% 이상

둘 다 **상품 수가 500개 미만**일 때만 창으로 친다. 수요가 올라도 공급이 이미 찼으면 늦은 것이다.

2번이 따로 필요한 이유: 12개월에 걸쳐 꾸준히 오르면 직전 12개월 평균 자체가 같이 올라가 배수가 눌린다. 배수만 보면 가장 좋은 후보를 놓친다.

## 6. 주간 자동 감시

```bash
python -m radar.cli scan --out out && python -m radar.cli diff --out out
```

`diff`는 지난 실행과 비교해 **바뀐 것만** 보고한다.

```
변화 3건
  [진입 창 열림] 피클볼 라켓세트 — 급등 4.2배, 상품 380개
  [판정 변경] 캠핑웨건: 보류 → 발주 검토
  [경쟁 완화] 무릎보호대: 0.71 → 0.44
```

`.github/workflows/sourcing-radar.yml`이 이걸 **매주 월요일 오전 9시(KST)** 자동 실행한다. 저장소 Settings → Secrets에 키 5개를 넣으면 끝이고, 진입 창이 열리면 이슈가 자동으로 열린다.

## 한계

- **쿠팡은 자동화하지 않았다.** 공개 API가 없고 스크래핑은 차단이 잦아 신뢰할 수 없다. 쿠팡 1페이지의 로켓배송 비율은 직접 세고, 15개 이상이면 `fulfillment_cost`를 채워라.
- **쇼핑성 점수는 자동 판정이 아니다.** 검색 시 쇼핑 영역이 뜨는지는 사람이 확인해 `shoppable` 열에 넣어야 한다.
- 검색광고 API의 `< 10` 응답은 5로 환산한다. 초저볼륨 키워드의 경쟁강도는 과대 추정될 수 있다.
